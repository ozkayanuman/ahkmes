## Sıradaki teknik uygulama

Tool Crib'in ilk kontrollü parçası olarak **fiziksel takım konum/durum
güncelleme komutu** uygulanacak.

Mevcut kanıt:

- `PhysicalToolInstance` zaten `location`, `status`, `version`, `lastUsedAt`
  alanlarına sahip.
- Tool durumları: `AVAILABLE`, `RESERVED`, `IN_USE`, `EXPIRED`, `BROKEN`,
  `QUARANTINED`, `RETIRED`.
- `ToolLifeEvent`, setup assignment ve life adjustment kayıtları mevcut.
- `ToolingService.adjustLife()` sürüm kontrollü (`version`) transaction,
  `ToolLifeEvent` ve audit örneğidir.
- Aktif/verified setup içindeki fiziksel takımın durumu `RESERVED` olmalıdır;
  rastgele status değişimi setup bütünlüğünü bozmamalı.

Önerilen ilk komutun sınırı:

- Shared schema: `location`, `status`, `version`, zorunlu `reason`.
- `RESERVED` veya `IN_USE` takımın konum/durumunu doğrudan değiştirmeyi
  reddet (önce setup release/operation completion akışını kullan).
- Yalnız uygun manuel durum geçişlerine izin ver (`AVAILABLE`, `BROKEN`,
  `QUARANTINED`, `RETIRED`; ömrü sıfır olan takım `EXPIRED` kalmalı).
- Transaction içinde version guard, `ToolLifeEvent` veya ayrı audit event,
  `AuditLog` ve mümkünse outbox kaydı.
- Controller endpoint ve Tooling UI action ekle; ardından servis birim testi,
  web typecheck ve `graphify update .`.

Bu, tam crate/stock/check-in-out tasarımı değildir; fiziksel resource state
değişimlerini güvenli ve izlenebilir hâle getiren temel adımdır.
